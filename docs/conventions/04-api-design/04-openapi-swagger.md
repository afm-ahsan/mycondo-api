# OpenAPI / Swagger Configuration

The OpenAPI specification is the **single source of truth** for the HTTP contract. It's:
- **Generated by the backend** (Swashbuckle + XML doc comments + endpoint metadata).
- **Consumed by the frontend** (TypeScript types and RTK Query hooks via codegen).
- **Hosted as Swagger UI** for human exploration in non-prod environments.

Hand-written API docs are forbidden. Drift is inevitable.

> Stack: **Swashbuckle.AspNetCore 6.x** + **Microsoft.OpenApi** + (optionally) **`Swashbuckle.AspNetCore.Annotations`** and **API Versioning** (`Asp.Versioning.Mvc.ApiExplorer` for `.NET 8/10`).

---

## 1. NuGet Packages

In `Directory.Packages.props`:

```xml
<PackageVersion Include="Swashbuckle.AspNetCore" Version="6.x" />
<PackageVersion Include="Swashbuckle.AspNetCore.Annotations" Version="6.x" />
<PackageVersion Include="Asp.Versioning.Mvc" Version="8.x" />
<PackageVersion Include="Asp.Versioning.Mvc.ApiExplorer" Version="8.x" />
```

Reference from `<Project>.Api.csproj`:

```xml
<PackageReference Include="Swashbuckle.AspNetCore" />
<PackageReference Include="Swashbuckle.AspNetCore.Annotations" />
<PackageReference Include="Asp.Versioning.Mvc" />
<PackageReference Include="Asp.Versioning.Mvc.ApiExplorer" />
```

### Rules

- **Swashbuckle, not the .NET 10 native `Microsoft.AspNetCore.OpenApi`** — for now. The native generator improves with each release, but Swashbuckle has the mature security UI, XML doc support, and operation-filter ecosystem we depend on. Migrate per-project when the native generator covers the gaps.
- **No `*.OpenApi.SwaggerUi`** preview packages. Stick to the stable line.

## 2. Folder Layout

```
src/<Project>.Api/
├── OpenApi/
│   ├── SwaggerSetup.cs                     # AddOpenApi(), UseSwaggerInDevelopment()
│   ├── ConfigureSwaggerOptions.cs          # IConfigureNamedOptions<SwaggerGenOptions> (versioning)
│   ├── AuthorizeOperationFilter.cs         # Adds 401/403 responses to authorized endpoints
│   ├── ProblemDetailsSchemaFilter.cs       # Documents the ProblemDetails shape
│   └── DescribeAllParametersInCamelCase.cs # Optional: query param naming
└── Program.cs
```

### Rules

- **All Swagger code lives in `Api/OpenApi/`** — never inline in `Program.cs` beyond the registration call.
- **One responsibility per filter class.** A class touches authorization OR schemas OR parameter naming, not all three.

## 3. Service Registration (Recommended Configuration)

```csharp
// Api/OpenApi/SwaggerSetup.cs
public static class SwaggerSetup
{
    public static IServiceCollection AddOpenApiServices(this IServiceCollection services)
    {
        services.AddEndpointsApiExplorer();

        // API Versioning — only when versioning is in use
        services.AddApiVersioning(options =>
        {
            options.DefaultApiVersion = new ApiVersion(1, 0);
            options.AssumeDefaultVersionWhenUnspecified = true;
            options.ReportApiVersions = true;
            options.ApiVersionReader = new UrlSegmentApiVersionReader();
        })
        .AddApiExplorer(options =>
        {
            options.GroupNameFormat = "'v'VVV";
            options.SubstituteApiVersionInUrl = true;
        });

        services.AddTransient<IConfigureOptions<SwaggerGenOptions>, ConfigureSwaggerOptions>();

        services.AddSwaggerGen(options =>
        {
            // --- Security: JWT Bearer ---
            options.AddSecurityDefinition("Bearer", new OpenApiSecurityScheme
            {
                Name = "Authorization",
                Type = SecuritySchemeType.Http,
                Scheme = "bearer",
                BearerFormat = "JWT",
                In = ParameterLocation.Header,
                Description = "JWT Authorization header using the Bearer scheme. Example: \"Bearer {token}\""
            });

            // --- Security: API Key (only if the project uses one) ---
            options.AddSecurityDefinition("ApiKey", new OpenApiSecurityScheme
            {
                Name = "X-Api-Key",
                Type = SecuritySchemeType.ApiKey,
                In = ParameterLocation.Header,
                Description = "API key for B2B / service-to-service integrations"
            });

            // --- Filters ---
            options.OperationFilter<AuthorizeOperationFilter>();   // adds 401/403 per endpoint
            options.SchemaFilter<ProblemDetailsSchemaFilter>();    // documents error shape

            // --- XML doc comments ---
            var xmlFile = $"{Assembly.GetExecutingAssembly().GetName().Name}.xml";
            var xmlPath = Path.Combine(AppContext.BaseDirectory, xmlFile);
            if (File.Exists(xmlPath))
                options.IncludeXmlComments(xmlPath, includeControllerXmlComments: true);

            // --- Stable operation IDs (drives codegen function names on FE) ---
            options.CustomOperationIds(api => api.TryGetMethodInfo(out var m) ? m.Name : null);

            // --- Treat all enums as strings in the schema ---
            options.UseAllOfToExtendReferenceSchemas();
            options.SupportNonNullableReferenceTypes();
            options.MapType<DateOnly>(() => new OpenApiSchema { Type = "string", Format = "date" });
            options.MapType<TimeOnly>(() => new OpenApiSchema { Type = "string", Format = "time" });

            // --- Annotations support ---
            options.EnableAnnotations();

            // --- Tag groups: group endpoints by aggregate ---
            options.TagActionsBy(api =>
            {
                var tag = api.GroupName ?? api.ActionDescriptor.RouteValues["controller"] ?? "Default";
                return new[] { tag };
            });
            options.DocInclusionPredicate((_, _) => true);
        });

        return services;
    }
}
```

### Rules

- **`Type = SecuritySchemeType.Http` + `Scheme = "bearer"`** — gives the Swagger UI the right "Authorize" affordance for JWTs (no need to type `Bearer ` manually).
- **No global `AddSecurityRequirement`.** Apply security per-endpoint via `AuthorizeOperationFilter` (see §6) so unauthenticated endpoints aren't falsely shown as authorized.
- **Custom operation IDs are stable** (`CustomOperationIds`) — they drive frontend codegen function names. Renaming a method changes the FE function name; do it deliberately.
- **`MapType<DateOnly>` / `MapType<TimeOnly>`** — Swashbuckle doesn't render these correctly out of the box.
- **`EnableAnnotations()`** lets you decorate endpoints/types with `[SwaggerOperation]`, `[SwaggerResponse]`, etc. when XML doc comments aren't enough.

## 4. Per-Version Document Configuration

When the API has multiple versions (`v1`, `v2`):

```csharp
// Api/OpenApi/ConfigureSwaggerOptions.cs
public sealed class ConfigureSwaggerOptions(
    IApiVersionDescriptionProvider provider
) : IConfigureNamedOptions<SwaggerGenOptions>
{
    public void Configure(SwaggerGenOptions options)
    {
        foreach (var description in provider.ApiVersionDescriptions)
        {
            options.SwaggerDoc(description.GroupName, CreateInfoForApiVersion(description));
        }
    }

    public void Configure(string? name, SwaggerGenOptions options) => Configure(options);

    private static OpenApiInfo CreateInfoForApiVersion(ApiVersionDescription description)
    {
        var info = new OpenApiInfo
        {
            Title = "<Project> API",
            Version = description.ApiVersion.ToString(),
            Description = $"<Project> HTTP API. {(description.IsDeprecated ? "**This version is deprecated.**" : string.Empty)}",
            Contact = new OpenApiContact { Name = "<Team>", Email = "<team>@<org>.com" },
            License = new OpenApiLicense { Name = "Proprietary" }
        };
        return info;
    }
}
```

### Rules

- **One `SwaggerDoc` per active version.** When v1 is deprecated and v2 ships, both still appear in the dropdown until v1 is decommissioned.
- **Deprecation flag visible in the description.** Frontend teams should see "this is going away" without reading a changelog.
- **For single-version APIs**, register one `SwaggerDoc("v1", ...)` directly in `AddSwaggerGen` and skip the versioning packages.

## 5. Single-Version Setup (Most Projects Start Here)

If the project is not yet versioned, replace the multi-doc block with a single static one:

```csharp
options.SwaggerDoc("v1", new OpenApiInfo

    Contact = new OpenApiContact { Name = "<Team>", Email = "<team>@<org>.com" }

```

Add versioning when the **first** breaking change is on the roadmap, not preemptively.

## 6. Authorize Operation Filter

A global `AddSecurityRequirement` marks every endpoint as authorized in the UI — including public endpoints. Use a filter instead so the lock icon and 401/403 responses appear only where they apply:

```csharp
// Api/OpenApi/AuthorizeOperationFilter.cs
public sealed class AuthorizeOperationFilter : IOperationFilter
{
    public void Apply(OpenApiOperation operation, OperationFilterContext context)
    {
        var hasAllowAnonymous =
            context.MethodInfo.GetCustomAttributes(true).OfType<AllowAnonymousAttribute>().Any() ||
            context.MethodInfo.DeclaringType?.GetCustomAttributes(true).OfType<AllowAnonymousAttribute>().Any() == true;
        if (hasAllowAnonymous) return;

        var hasAuthorize =
            context.MethodInfo.GetCustomAttributes(true).OfType<AuthorizeAttribute>().Any() ||
            context.MethodInfo.DeclaringType?.GetCustomAttributes(true).OfType<AuthorizeAttribute>().Any() == true ||
            context.ApiDescription.ActionDescriptor.EndpointMetadata.OfType<AuthorizeAttribute>().Any();
        if (!hasAuthorize) return;

        operation.Responses.TryAdd("401", new OpenApiResponse { Description = "Unauthorized" });
        operation.Responses.TryAdd("403", new OpenApiResponse { Description = "Forbidden" });

        operation.Security ??= new List<OpenApiSecurityRequirement>();
        operation.Security.Add(new OpenApiSecurityRequirement
        {
            [new OpenApiSecurityScheme
            {
                Reference = new OpenApiReference { Type = ReferenceType.SecurityScheme, Id = "Bearer" }
            }] = Array.Empty<string>()
        });
    }
}
```

### Rules

- **Detects both attribute-based and Minimal-API authorization metadata.** Works whether you use `[Authorize]` on controllers or `RequireAuthorization()` on endpoint groups.
- **`AllowAnonymous` wins.** A login endpoint inside an authorized group is still rendered as public.
- **Adds 401/403 responses automatically** so you don't have to repeat `.ProducesProblem(401)` on every endpoint.

## 7. Documenting Endpoints

### Minimal APIs

```csharp
group.MapPost("/", CreateAsync)
     .WithName("CreateCustomer")                                  // → operationId "CreateCustomer"
     .WithSummary("Create a new customer")
     .WithDescription("Creates a customer with the given name and email. Returns 201 with a Location header.")
     .Produces<CustomerDto>(StatusCodes.Status201Created)
     .ProducesValidationProblem()                                 // 400
     .ProducesProblem(StatusCodes.Status409Conflict);
```

### Controllers (when controllers are unavoidable)

```csharp
/// <summary>
/// Creates a new customer.
/// </summary>
/// <param name="command">Customer creation payload.</param>
/// <param name="ct">Cancellation token.</param>
/// <response code="201">The customer was created.</response>
/// <response code="400">Validation failed.</response>
/// <response code="409">A customer with that email already exists.</response>
[HttpPost]
[ProducesResponseType(typeof(CustomerDto), StatusCodes.Status201Created)]
[ProducesResponseType(typeof(ValidationProblemDetails), StatusCodes.Status400BadRequest)]
[ProducesResponseType(typeof(ProblemDetails), StatusCodes.Status409Conflict)]
public async Task<IActionResult> Create([FromBody] CreateCustomerCommand command, CancellationToken ct) { ... }
```

### Rules

- **Every endpoint has `Produces<T>` for success and `ProducesProblem` for documented errors.** Missing metadata = lying OpenAPI = broken codegen.
- **`WithName(...)` / `[HttpPost(Name = "...")]`** is the operation ID. Treat it as part of the public contract.
- **Summary in 5–10 words.** The description carries detail. Both render in Swagger UI.
- **One operation per route+method.** Don't multiplex.
- **Tag by aggregate** (`.WithTags("Customers")` on the group) so endpoints group naturally.

## 8. Documenting Schemas

DTOs are picked up automatically. Comment them with XML doc:

```csharp
/// <summary>
/// A customer record.
/// </summary>
public sealed record CustomerDto(
    /// <summary>Customer ID (UUIDv7).</summary>
    Guid Id,
    /// <summary>Display name.</summary>
    string Name,
    /// <summary>Lowercased email address.</summary>
    string Email,
    /// <summary>Status: Active | Inactive.</summary>
    string Status,
    /// <summary>UTC creation timestamp.</summary>
    DateTimeOffset CreatedAtUtc);
```

### Schema filters for shared types

`ProblemDetails` is referenced everywhere; document it once:

```csharp
public sealed class ProblemDetailsSchemaFilter : ISchemaFilter
{
    public void Apply(OpenApiSchema schema, SchemaFilterContext context)
    {
        if (context.Type != typeof(ProblemDetails) && context.Type != typeof(ValidationProblemDetails))
            return;

        schema.Description = "RFC 9457 Problem Details for HTTP APIs.";
        if (schema.Properties.TryGetValue("traceId", out var trace))
            trace.Description = "Correlation ID echoed from the request's X-Correlation-Id header.";
    }
}
```

### Rules

- **Enable XML doc comments** on the API project (`<GenerateDocumentationFile>true</GenerateDocumentationFile>` is set globally in `Directory.Build.props`).
- **`PropertyNamingPolicy.CamelCase`** in JSON — Swashbuckle picks it up automatically.
- **Strongly-typed IDs** (e.g. `CustomerId`) need a JSON converter and a Swashbuckle map so they render as `string`/`uuid`, not as nested objects.

## 9. Per-Environment Behavior

| Environment   | Swagger UI                                | OpenAPI JSON                              |
|---------------|-------------------------------------------|-------------------------------------------|
| Development   | **On.** Anonymous access at `/swagger`.   | At `/swagger/v1/swagger.json`.            |
| Staging       | **On.** Behind authentication or VPN.     | Same.                                     |
| Production    | **Off** (or behind authentication).       | Internal-only via separate route.         |

```csharp
// Program.cs (after middleware pipeline is built)
app.UseSwaggerInDevelopmentOrFlagged(builder.Configuration);

public static WebApplication UseSwaggerInDevelopmentOrFlagged(this WebApplication app, IConfiguration cfg)
{
    var enabled = app.Environment.IsDevelopment() || cfg.GetValue<bool>("Swagger:Enabled");
    if (!enabled) return app;

    app.UseSwagger(options =>
    {
        options.RouteTemplate = "swagger/{documentName}/swagger.json";
    });

    app.UseSwaggerUI(options =>
    {
        // Multi-version: enumerate from IApiVersionDescriptionProvider
        var versionProvider = app.Services.GetService<IApiVersionDescriptionProvider>();
        if (versionProvider is not null)
        {
            foreach (var v in versionProvider.ApiVersionDescriptions)
                options.SwaggerEndpoint($"/swagger/{v.GroupName}/swagger.json", $"<Project> API {v.GroupName}");
        }
        else
        {
            options.SwaggerEndpoint("/swagger/v1/swagger.json", "<Project> API v1");
        }

        options.RoutePrefix = "swagger";
        options.DocumentTitle = "<Project> API";
        options.DefaultModelsExpandDepth(2);
        options.DocExpansion(DocExpansion.List);
        options.EnableDeepLinking();
        options.DisplayOperationId();
        options.EnableFilter();
        options.EnableTryItOutByDefault();
    });

    return app;
}
```

### `appsettings.{Environment}.json`

```jsonc
// appsettings.Development.json
{ "Swagger": { "Enabled": true } }

// appsettings.Production.json
{ "Swagger": { "Enabled": false } }
```

### Rules

- **Development and Staging always have Swagger.** Production defaults to off.
- **If production needs Swagger** (e.g. for a B2B partner integration UI), gate it with `RequireAuthorization()`.
- **Don't strip the OpenAPI JSON** from production builds — internal tooling and integration tests can still hit `/swagger/v1/swagger.json` even when the UI is disabled, as long as the route is reachable.

## 10. Frontend Codegen from OpenAPI

The OpenAPI spec drives frontend types and (optionally) RTK Query hooks.

### Approach 1: Types only (recommended default)

```jsonc
// <Project>.Client/package.json
{
  "scripts": {
    "openapi:gen": "openapi-typescript http://localhost:5000/swagger/v1/swagger.json -o src/api/generated/types.ts"
  },
  "devDependencies": {
    "openapi-typescript": "^7.x"
  }
}
```

Hand-write RTK Query slices but use the generated types.

### Approach 2: Hooks + types (full codegen)

```jsonc
{
  "scripts": {
    "openapi:gen": "openapi-codegen --config codegen.config.ts"
  }
}
```

Tools: `@rtk-query/codegen-openapi` or `orval`. Generated slices are checked into the repo.

### Rules

- **Generated files live in `src/api/generated/`** and are read-only. Never hand-edit.
- **Regenerate as part of the FE build** when the backend contract changes — and commit the diff so reviewers see API drift.
- **`operationId` becomes the function name.** Stable IDs are why §3 sets `CustomOperationIds`.
- **Run codegen against the staging contract for production builds** to catch drift before deploy.

## 11. Idempotency and Correlation Headers in OpenAPI

Document the cross-cutting headers once and reference them per operation:

```csharp
options.OperationFilter<HeaderAwareOperationFilter>();

public sealed class HeaderAwareOperationFilter : IOperationFilter
{
    public void Apply(OpenApiOperation operation, OperationFilterContext context)
    {
        // Idempotency-Key on POST/DELETE
        var method = context.ApiDescription.HttpMethod;
        if (method is "POST" or "DELETE")
        {
            operation.Parameters.Add(new OpenApiParameter
            {
                Name = "Idempotency-Key",
                In = ParameterLocation.Header,
                Required = false,
                Description = "Client-generated UUIDv7 used to deduplicate retried requests.",
                Schema = new OpenApiSchema { Type = "string", Format = "uuid" }
            });
        }

        // X-Correlation-Id always
        operation.Parameters.Add(new OpenApiParameter
        {
            Name = "X-Correlation-Id",
            In = ParameterLocation.Header,
            Required = false,
            Description = "Correlation ID propagated through the request. Server generates one if absent.",
            Schema = new OpenApiSchema { Type = "string", Format = "uuid" }
        });
    }
}
```

### Rules

- **Cross-cutting headers documented in one filter**, not per-endpoint.
- **`required: false`** — server generates them when missing.

## 12. Validation in Swagger Try-It-Out

For the UI to validate inputs and show useful examples:

- **DTO records carry `[Required]`, `[StringLength]`, `[Range]`** on optional metadata properties — Swashbuckle reflects them. We prefer FluentValidation for runtime, but data annotations help the UI render hints.
- **`SwaggerSchema(Description = "...", Example = ...)`** from `Swashbuckle.AspNetCore.Annotations` for richer per-property hints.
- **Don't duplicate validation logic.** FluentValidation is the source of truth for runtime; annotations are documentation.

## 13. Common Mistakes

| Mistake                                                                      | Fix                                                                                  |
|------------------------------------------------------------------------------|--------------------------------------------------------------------------------------|
| Global `AddSecurityRequirement(...)` in `AddSwaggerGen`                      | Use an operation filter; respect `[AllowAnonymous]`                                  |
| Endpoint missing `Produces<T>` / `ProducesProblem`                           | OpenAPI lies; codegen produces wrong return types                                    |
| `operationId` changes per release because methods get renamed                | `CustomOperationIds` based on `MethodInfo.Name`; rename intentionally                |
| `XML documentation file` not generated → empty Swagger descriptions          | Set `<GenerateDocumentationFile>true</GenerateDocumentationFile>` (in `Directory.Build.props`) |
| Two API versions, one `SwaggerDoc`                                           | Iterate over `IApiVersionDescriptionProvider.ApiVersionDescriptions`                 |
| Anonymous Swagger UI exposed in production                                   | `Swagger:Enabled` flag; default off in Production; gate with `RequireAuthorization`  |
| `DateOnly` / `TimeOnly` rendered as objects                                  | `options.MapType<DateOnly>(...)`                                                     |
| Strongly-typed IDs serialized as `{ value: "..." }` in OpenAPI               | Add a JSON converter + `MapType<TId>(() => new OpenApiSchema { Type = "string", Format = "uuid" })` |
| `Bearer` lock icon visible on `/auth/login`                                  | `AllowAnonymous` + filter respects it                                                |
| FE bundles drift from BE because codegen runs only locally                   | Run codegen in CI and fail on diff                                                   |
| `EnableTryItOutByDefault()` left on in production where Swagger is exposed   | Disable for production-exposed UIs to discourage casual mutations                    |
| `Swagger UI custom CSS/JS` referenced files that don't exist                 | Either ship them under `wwwroot` or remove the calls                                 |
| Mixing global `AddSecurityRequirement` with per-operation filter             | Pick one — operation filter is preferred                                             |
| `[ApiVersion("1.0")]` on controllers but no `AddApiExplorer` registered      | Swagger doesn't see versions; UI dropdown shows nothing                              |
| Two security definitions but UI only shows one                               | Both must be added via `AddSecurityDefinition`; the operation filter chooses which to attach |
